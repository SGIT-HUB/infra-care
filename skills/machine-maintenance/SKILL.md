# 本机综合维护

维护通用方法和当前机器状态，并让下一次会话可以从本地档案接续。

## 定位与识别

优先使用用户指定的 infra-care 根目录，其次使用当前工作目录中的项目入口。安装副本可读取同目录下仅保存在本机的 local-root.txt。找不到入口时请求用户提供位置，不猜测其他机器的固定路径。

读取仓库 AGENTS.md。仅整理公共文档时，直接查阅相关主题；需要读取 local/ 或操作实际环境时，先按 [机器识别与档案](references/机器识别与档案.md) 比对当前机器与 local/machine.json。未核实身份前，不沿用旧路径、凭据或“已验证”结论，也不清理旧记录。

核实后读取 local/维护档案.md、任务所需专题和本机偏好。新机器只保留当前机器档案，按授权清理复制来的旧维护记录；清理范围不包含服务数据、数据库或仓库外文件。

## 按任务处理

| 任务 | 核对重点 |
|---|---|
| 软件安装与配置 | 当前版本、官方要求、程序与数据位置、实际生效状态 |
| Docker 与 WSL | 应用、运行组件、发行版磁盘、数据卷、交换文件分别核对 |
| 网络与代理 | 网卡路由、DNS、系统代理、客户端与出口分别定位 |
| OpenResty stream 空闲断连 | 按需读取 [连接超时排查](references/OpenResty-stream-连接超时排查.md)，区分代理、客户端和后端超时 |
| Linux 服务日志轮转 | 按需读取 [日志轮转](references/Linux-日志轮转.md)，先确认日志去向与服务重开机制 |
| Windows 磁盘任务 | 按需读取仓库 skills/windows-disk-maintenance/SKILL.md |
| Linux 与 macOS | 使用本平台原生工具和官方说明，不执行 Windows 专项命令 |
| 归档与接续 | 实际路径、挂载、连接信息位置、验证结果和剩余工作 |

按用户任务和已有授权推进，不额外生成维护脚本、统一编排或后台任务。配置文件写入不等于已生效，Docker 应用窗口出现不等于引擎已就绪。

先根据当前问题选择专题，不默认读取全部 references/。专题提供判断依据，阅读不等于授权执行变更。

只有用户明确要求启用或使用 ClamAV，才读取对应技能正文并执行相关任务。一般维护不探测、安装、更新或运行它。

## 写回

维护后更新 local/ 的实际事实，区分已验证、写入待生效、历史记录和建议未执行。真实凭据存于本机受限位置，记录其位置，不复制到公开技能。

临时文档备份只放 backups/，验证完成后及时清理。公共变更只包含通用技能、说明及脱敏示例，提交前检查暂存内容。示例放 examples/，统一以“示例-”命名并注明未部署。

任务结束后按仓库 CONTRIBUTING.md 的“知识维护”约定整理本次经验：先检索已有主题，优先就地纠错或合并，直接形成可查看的工作区差异。没有可复用增量就不新增；未做运行验证的知识不能写成已部署或已生效。
