# 机器识别与档案

本流程用于防止克隆或复制目录后误用旧机器记录，不是后台识别服务。

## 读取身份

先只读收集当前操作系统、机器名称、稳定系统标识和物理网卡 MAC。过滤虚拟网卡，不把当前连接的某一个 MAC 当作唯一机器身份。

| 平台 | 稳定标识来源 | 辅助信息 |
|---|---|---|
| Windows | 注册表 HKLM\\SOFTWARE\\Microsoft\\Cryptography 的 MachineGuid | 机器名、Get-NetAdapter -Physical 的 MAC |
| Linux | /etc/machine-id | hostname、物理网络接口 MAC |
| macOS | IOPlatformExpertDevice 的 IOPlatformUUID | 机器名称、物理网络接口 MAC |

platform 统一用 windows、linux、macos。原始系统标识不写入公开文件。machineIdHash 使用 SHA-256：对“规范化平台名 + 空字符 + 去除两端空白并转小写的稳定系统标识”的 UTF-8 字节计算哈希。MAC 仅保存于 local/machine.json；没有可靠稳定标识时，注明识别不充分，不仅凭 MAC 执行清理。

## 比对规则

- 没有 local/machine.json：创建本机身份，并据实际检查建立本机记录。不要把示例或残留记录当作本机事实。
- 稳定标识哈希与平台相同：通常为同一机器。机器名或 MAC 改变时核实改名、换网卡或随机 MAC，更新辅助信息，不据此删除记录。
- 稳定标识不同：视为复制到另一机器的候选，核对机器名、MAC 和实际平台后确认。
- 信息缺失、占位值、克隆系统标识或证据冲突：先只读核对，不自动删除。

## 新机器记录

用户要求在新机器接续维护、且已确认目录内是复制来的旧机器记录时：

1. 列明 local/ 中待替换的维护文档，确认不是应用数据、唯一资料、凭据源文件或外部链接。
2. 仅将这些旧记录暂存至 backups/ 下本次操作的唯一目录，保护敏感内容；不把它们加入 Git。
3. 按当前机器实际检查建立 local/machine.json 和 local/维护档案.md；其他专题按当前任务需要建立。
4. 核对新档案身份、引用和实际状态，再清理本次临时备份。保留仓库中的通用技能和示例。
5. 如果授权范围不包含旧记录清理，或无法确认其用途，保留数据并说明需要核实的对象，不扩大删除。

此流程只管理维护记录。不得卸载软件、注销 WSL 发行版、删除 Docker 卷、清理数据库或删除仓库外数据来“切换机器”。

## 本机目录

- local/machine.json：当前机器身份和最后核对时间。
- local/维护档案.md：实际部署、维护结论和待办。
- local/软件配置与使用.md：按需要维护的软件专题。
- local/容器挂载与连接信息.md：按需要维护的挂载和凭据文件位置。
- local/偏好与约定.md：当前机器的用户偏好。

示例见仓库 examples/。首次创建身份需实际采集，不能只将示例中的标记改成“已验证”。
