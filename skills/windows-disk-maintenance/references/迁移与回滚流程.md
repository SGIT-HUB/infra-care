# 迁移与回滚流程

本流程适用于经过确认的 Windows 数据目录。具体命令应根据本机检查和用户授权生成；本文件不提供一键迁移或删除脚本。

## 1. 核实路径和依赖

形成一张操作表：源路径、实际目标、拟用目标、备份路径、使用该目录的应用、内部链接、验证动作、失败时的恢复动作。

- 路径必须是经过确认的绝对路径。解析路径及祖先目录的联接关系；源、目标、备份不能相同或相互包含，也不能经过联接落到同一位置。
- 确认目标卷稳定可用、支持所选机制、权限合适，并能容纳待复制数据和必要余量。已有目标仅在证实属于同一次迁移且内容关系明确后，才允许增量继续。
- 确认源是预期普通目录；已经是 Junction 时，先分析真实目标。确认备份名未被占用，不覆盖旧备份。
- 不跟随重解析点，列出内部 Junction、符号链接及目标。记录外部依赖，判断哪些绝对链接需要在切换后仍能解析到正确数据；识别循环、悬空链接和指向备份的链接。
- 关闭相关应用、后台服务、终端和写入者。需要迁移执行器自身的数据时，将操作安排到完全退出执行器后的独立会话。

## 2. 复制、切换和验证

1. 先复制，保留原目录。使用 Robocopy 时根据本机要求选择数据、时间和 ACL 的复制参数；包含链接时检查 `/SJ /SL` 的支持与适用性，不使用会删除目标额外文件的 `/MIR /PURGE`，也不以 `/MOVE` 代替可回滚的复制。
2. 立即保存并检查复制退出码和日志。Robocopy `>= 8` 表示失败；`0–7` 仍需查看差异、额外文件与不匹配项，不能据此宣告应用可用。
3. 核对实际文件、关键数据、权限及链接。`/SJ /SL` 用于复制链接本身，不代表链接目标已经适配新布局；分别检查切换前后最终解析位置。必要时按已核实的映射重建内部链接，不能批量字符串替换未知目标。
4. 源目录改为唯一备份名，`Rename-Item` 使用 `-LiteralPath` 与 `-ErrorAction Stop`。改名失败立即停止，不建立联接。
5. 在已空出的原入口建立指向新目标的 Junction；不使用强制覆盖。建联失败时，确认原入口确实空缺，才将备份改回原名；入口出现未知对象则停止并保留两份数据。
6. 验证入口类型与目标、内部链接最终位置、应用启动和实际读写。针对迁移内容选择验证：例如 SDK 可执行文件应实际运行，而不只检查路径存在。保留迁移前后证据。
7. 验证后仍保留备份，直到用户明确授权清理。保留原盘备份期间，原盘空间通常尚未释放；不能把目标盘新增副本算作释放收益。

Robocopy 的链接参数和退出码以 [Microsoft Robocopy 文档](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/robocopy) 为依据。链接目标、应用兼容性和回滚条件仍需本机验证。

## 3. 清理备份或缓存

清理前确认具体绝对路径在已授权目录内，核对其实际落盘位置、是否仍被使用、是否含重解析点，以及是否保存唯一数据。逐项区分“删除联接入口”“删除目标数据”“删除旧备份”。

删除联接入口只能使用已确认仅作用于链接本身的方法，不递归跟随目标。对于有内部链接的备份，不直接递归删除整棵树；先核对并处理链接入口，确保目标数据不受影响。

Windows 文件操作在同一执行环境内使用原生 API 或 `-LiteralPath` 参数，不将 PowerShell 枚举结果拼成 `cmd /c` 删除命令。遇到超长路径，先核实当前 PowerShell/.NET 对路径的支持，再使用支持该路径的原生方式；不能通过扩大删除范围解决错误。

文件被占用、权限失败或路径身份变化时停止该项，保留已成功与未成功的结果；不自动提权、夺取所有权或重试强删。操作后复核残留和卷可用空间。

## 4. 回滚：先决定哪份数据是最新的

### 尚未产生新数据

关闭写入者，确认旧备份仍完整且适用，再确认当前入口确实指向预期目标。仅移除联接入口，将备份恢复原名，并验证内部链接、应用和读写。保留目标盘副本以供核查。

### 切换后已写入，或是否写入不确定

当前目标数据可能比旧备份更新，不能直接恢复旧备份并宣称无损。

1. 停止全部写入者，确认当前有效数据集，并检查源盘能否容纳最新数据的完整副本，同时保留旧备份。
2. 将最新数据复制到源盘一个新建、独立的暂存目录。不要直接合并到旧备份，以免复活已删除文件或覆盖新版本。保留当前入口直到新副本验证通过。
3. 核对新增、修改及删除状态；校验关键文件。按最终布局检查并调整内部链接，使回滚后应落在源盘的数据不再依赖迁移盘。
4. 仅移除已确认的当前 Junction，将暂存目录改为原名。若切换失败且入口仍空缺，恢复指向当前有效目标的联接；有未知对象时停止。
5. 验证最新数据、应用读写和内部链接，记录新的有效副本。原目标和旧备份分别保留，清理各自需要相应授权。

如果源盘空间不足或两边数据冲突，保留当前可用入口与全部副本，说明具体阻塞，先解决空间或数据取舍。用户明确要求回到旧时间点时，先说明将放弃哪些后续数据，再按授权处理。
